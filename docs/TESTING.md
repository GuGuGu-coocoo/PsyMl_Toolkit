## 中文

先按开发者指南安装依赖，在项目根目录运行。测试全部使用合成数据；不要替换为参与者数据。

- `tests/`：Python 核心自动测试，位于根目录下一层。
- `gui/tests/`：GUI 与核心桥接、完整流程、滚动、多语言及独立验证测试。
- `examples/quickstart/`：用户试用的分类、回归配置，48 行训练数据与各 10 行预测数据。
- `examples/synthetic/`：旧开发夹具与格式矩阵；`two_groups.csv` 用于边界检查。
- `examples/public/`：可选公开数据示例，需要额外下载；默认快速测试不需要。

这些命令在完整源码检出中执行，独立应用包不包含开发测试环境。隐私审计还需要 `legacy/` 中的历史夹具；只有源码副本明确不含该目录时，才跳过 `tools/audit_repository.py`。源码检出当前为正式版本 `0.3.0`（单一版本源），包含 Phase A–D 新功能与两轮人工反馈修复（第一轮 FR-012–FR-016，第二轮 FR-016 补充与 FR-017–FR-020）；独立包与分发 PDF 的可下载附件以 [Releases](https://github.com/GuGuGu-coocoo/PsyMl_Toolkit/releases) 页面为准，v0.2.0 及更早的下载包与分发 PDF 不含这些功能与修复。第 4 页预测结果与系数区块的截图已随本轮界面更新（`docs/images/*/10-prediction-results.png`、`12-coefficients.png`），其余截图仍是修复前的界面。发布候选的 ZIP、PDF 与 SHA-256 由 `tools/verify_release_artifacts.py` 实际读取内容核验，不检查日志成功字符串。

```bash
uv sync --locked --group dev
uv run ruff check src tests tools
uv run pytest -q
uv run python tools/audit_repository.py
uv build
```

GUI 自动检查需要 Godot 4.7.2。macOS/Linux 先运行 `export PSYML_PYTHON="$PWD/.venv/bin/python"`；Windows PowerShell 先运行 `$env:PSYML_PYTHON = (Resolve-Path .venv/Scripts/python.exe).Path`，再运行：

```bash
uv run --extra explain python tools/run_gui_tests.py --validate
uv run --extra explain python tools/run_gui_tests.py
```

`tools/run_gui_tests.py` 逐组运行 12 个 headless GUI 测试（`--group <名称>` 可只跑一组，`--list-groups` 列出组名/脚本/完成标记，`--timeout` 设置每组超时，默认 600 秒）。每组必须同时满足退出码 0、输出含该组 `PSYML_*_OK` 完成标记、且不含 `SCRIPT ERROR` 或 `_FAILURE` 标记才算通过；Godot 可能打印脚本错误后仍以 0 退出，所以只检查退出码不够。每组输出边产生边刷新到控制台与 `tmp/ci-gui/NN-<组名>.log`（`--log-dir` 或 `PSYML_GUI_LOG_DIR` 可改），因此某组超时或崩溃时日志文件仍保留已产生的输出；完整通过/失败汇总总会打印，失败时给出该组日志路径。CI 失败时 `tmp/ci-gui` 会作为 7 天短期测试 artifact 上传（复用仓库已有固定 SHA 的 upload-artifact，无新增权限、不发布 Release，目录只含合成测试日志）。完整流程组 `ui_flow` 等待真实分析结果的默认上限为 30 秒（`PSYML_TEST_RUN_TIMEOUT_SECONDS` 可调整，仅改等待不改断言），失败时写出 `ui_flow_failure.txt`，含状态 key、规范化与原始期望/实际路径、`result.json` 是否存在、桥接子进程是否运行与退出码，以及有限的 stderr 尾部（不含研究数据行）。逐组等价命令（如需手工调试）：

```bash
godot --headless --path gui --script res://tests/test_bridge.gd
godot --headless --path gui --script res://tests/test_ui_flow.gd
godot --headless --path gui --script res://tests/test_feedback.gd
godot --headless --path gui --script res://tests/test_parameter_context.gd
godot --headless --path gui --script res://tests/test_independent_results.gd
godot --headless --path gui --script res://tests/test_config_import.gd
godot --headless --path gui --script res://tests/test_prediction.gd
godot --headless --path gui --script res://tests/test_permutation.gd
godot --headless --path gui --script res://tests/test_data_check.gd
godot --headless --path gui --script res://tests/test_interpretation_results.gd
godot --headless --path gui --script res://tests/test_explanation.gd
godot --headless --path gui --script res://tests/test_coefficients.gd
```

`tools/run_gui_tests.py` 按优先级解析 Godot：`--godot` 显式路径/命令、`GODOT`、必要时的 `GODOT4`、最后 PATH 上的 `godot`。命中的入口都会经 `Path.resolve()` 解析，因此安装器在 Windows 创建的无后缀链接（如 `C:\Users\runneradmin\bin\godot`）与含空格目录会执行真实 `.exe`，全程不经过 shell。路径无效或所有候选都不存在时，错误会列出尝试过的选项并返回非零。`--validate` 用同一可执行文件运行 `--headless --editor --path gui --quit` 并等待进程结束，要求退出码 0、输出含 `Godot Engine v` 启动横幅且无 `SCRIPT ERROR`/`_FAILURE`；这避免 PowerShell 直接调用 GUI 子系统程序立即返回、把未加载项目的“成功”当成验证通过。上面的逐组命令假定 `godot` 可直接在 shell 中调用；Windows 的无后缀链接不能这样调用，请改用 `--group <名称>` 走 runner（或使用解析后的真实路径）。

单样本 SHAP 解释的可选依赖单独安装：`uv sync --extra explain`（或 `uv pip install -e ".[explain]"`）。未安装时 `tests/test_explanation.py`、`tests/test_explanation_cli.py` 与 `gui/tests/test_explanation.gd` 会跳过或明确报缺依赖；普通预测始终可用。首次运行会触发 numba JIT 与 matplotlib 字体缓存，可能较慢；把 `NUMBA_CACHE_DIR`、`MPLCONFIGDIR`、`PSYML_TEST_TMP` 指向项目 `tmp/phase-C-worker/` 下。自动检查覆盖累计瀑布分段（base→output、TopN+余项）、绘图端点使用与核心一致的 atol/rtol、GUI 产物查看/打开与跨切换保留、计算中上下文阻止、取消后立即重启、分片 JSON 与大 stderr；CLI `explain --output-dir` 的导出仍只写新建/空目录，目标非空时新建唯一子目录且不改动已有同名 CSV/模型/背景，同源目录、缺产物与复制失败都报错且不留成功标记，并拒绝非空输出目录与 `--overwrite`（界面自 FR-020 起不再提供导出入口）。真实窗口外观与多变量 CJK 图仍需人工看图，自动通过不替代。

拟合系数（FR-005）不需要 `explain` 依赖：`tests/test_coefficients.py` 覆盖逐族系数/截距重建、`drop`+`none` 恒等 passthrough、类别值/类型与下划线标签、全缺失列删除记录、编码 `drop_idx_`/逐列映射、训练 dtype 来源、二分类 LDA 的 sigmoid=概率与多类 logistic softmax=概率等轴语义，以及核验失败（超限/形状不符/非有限）返回 `error` 并拒绝写出；`tests/test_coefficients_cli.py` 覆盖 CLI 导出/拒绝覆盖/未核验与失败不写；`gui/tests/test_coefficients.gd` 覆盖结果页系数状态与打开入口、逐输出轴截距/单位/拟合范围显示、切换语言与无导出入口。`gui/tests/test_explanation.gd` 增加背景行不换行/不成列的布局断言。

人工快速检查：打开分类样例，目标选 `target`、分组选 `participant`，预测变量仅 `score`、`category`，模型选 Decision Tree 和 Dummy，分组 K 折、外层 3、内层 2；选择不指定主要验证，并加选留出法。运行后应先显示验证选择提示，切换后分别显示完整结果。切换三种语言、检查结果与配置是否保持；确认软件名下方版本小字与源码 `src/psyml/__init__.py` 的 `__version__`（独立包为包内 `BUILD.json`，同一常量生成）一致，当前源码版应显示正式版本号 `0.3.0`；在研究设计和结果摘要文字处测试滚轮/触控板：从整页起手经过小表格仍滚动整页、从小表格起手只滚动该表格、停顿约 250 ms 后重新起手才可换层，且滚动起手后立即点击另一个列表或拖动滚动条仍能正常选中/移动（锁定只作用于滚轮/滑动）；再运行回归配置并检查回归指标与图形。第 2 页新训练结果应落在结果根目录的 `training/run_*`；第 4 页确认输出根目录行与第 2 页一致，预测写入 `prediction/run_*/predictions.csv`（可直接打开，且“打开预测结果文件夹”打开运行目录而不是 CSV），SHAP 与系数分别落在 `explanation/`、`coefficients/` 的 `run_*` 新目录，三块都没有导出入口，旧版直接放在根目录的 `run_*` 仍能打开且不被改写；运行收尾时应显示“正在整理并写出结果…”且进度条未满，完成后才进入结果页。报错、终止与重试也应分别复测。

自动测试通过不等于真实研究设计已验证。少于两个测试样本的 R² 边界测试会有预期警告。CI 在 Windows、macOS、Linux 上运行，使用 `uv sync --locked --group dev --extra explain` 安装锁定环境，因此 SHAP 相关测试会真实执行而不是跳过，并通过 `tools/run_gui_tests.py` 运行全部 12 组 GUI 检查（项目验证步骤 `--validate` 也走同一 runner 与解析后的真实可执行文件）；GUI 步骤失败时 `tmp/ci-gui` 逐组日志会作为短期测试 artifact 保留（只含合成测试日志，无新增权限、不发布 Release），使某平台失败时仍能看到完整分组日志与汇总；所有需要 SHAP 的 `uv run` 步骤（`uv run --extra explain pytest -q`、传递 `PSYML_PYTHON` 的步骤与 GUI runner）都显式带 `--extra explain`，避免同步时移除 extra；查看对应提交的 CI 状态，不把本地测试等同于其他平台已通过。`.github/workflows/native-test-build.yml` 的手动 Windows 测试构建同样安装 `explain` 与 `build`，并运行 A/C/D bundle smoke（置换/解释/系数）；发布时 macOS 与 Windows 两侧都保留 `explain` 依赖与这三类 smoke。它只保留测试产物，不发布 Release，其定义改动也不代表 Windows 原生已验证。

## English

Install as described in the developer guide and run the commands above from the project root. `tests/` contains core tests, `gui/tests/` GUI tests, and `examples/synthetic/` adjacent CSV/JSON pairs. Public datasets are optional. Tests use synthetic data only. Run these commands in a source checkout, not a standalone app archive. The privacy audit additionally requires `legacy/`; skip it only when that directory is absent from the source copy. The source checkout is now the official `0.3.0` (single version source) with the Phase A–D features and both rounds of human-feedback fixes (first round FR-012–FR-016; second round FR-016 supplement and FR-017–FR-020); the standalone packages and distribution PDFs available for each version are those listed on the Releases page, while the v0.2.0 and earlier packages and PDFs do not contain these features or fixes. Release candidates are checked by `tools/verify_release_artifacts.py`, which reads the actual ZIP/PDF contents and hashes instead of a success string in a log.

Set `PSYML_PYTHON` to the installed environment: `.venv/bin/python` on macOS/Linux, `.venv/Scripts/python.exe` on Windows. The platform-specific commands above configure it. Godot 4.7.2 is required for GUI checks. `tools/run_gui_tests.py` runs all 12 headless GUI groups one by one (`--group <name>` for a single group, `--list-groups` to list names/scripts/markers, `--timeout` for the per-group limit, default 600 s). A group passes only when it exits 0, prints its `PSYML_*_OK` completion marker and logs no `SCRIPT ERROR` or `_FAILURE` marker; Godot can print script errors and still exit 0, so the exit code alone is not enough. Each group streams its output to the console and to `tmp/ci-gui/NN-<group>.log` (override with `--log-dir` or `PSYML_GUI_LOG_DIR`) as it is produced, so a timed-out or crashed group still leaves its partial output in the file; the full pass/fail summary is always printed and failures name their log. On CI failure `tmp/ci-gui` is uploaded as a 7-day test artifact (reusing the repository's pinned upload-artifact, no added permissions, no release; the directory only holds synthetic test logs). The full-flow `ui_flow` group waits up to 30 s by default for a real analysis (`PSYML_TEST_RUN_TIMEOUT_SECONDS` may raise the wait, never the assertions); on failure it writes `ui_flow_failure.txt` with the status key, canonical and raw expected/actual directories, whether `result.json` exists, bridge process state and exit code, and a bounded stderr tail (no research data rows). The per-group commands listed above are equivalent for manual debugging. The runner resolves Godot in this order: an explicit `--godot` path or command, then `GODOT`, then `GODOT4`, then the `godot` command on PATH, and resolves every hit with `Path.resolve()`, so the installer's spaced directories and the extensionless Windows link (for example `C:\Users\runneradmin\bin\godot`) execute the real `.exe` without a shell; an invalid path or no candidate at all produces an error naming what was tried and a non-zero exit. `--validate` runs `--headless --editor --path gui --quit` with that same executable, waits for it and requires exit 0, the `Godot Engine v` banner and no `SCRIPT ERROR`/`_FAILURE`, so PowerShell's immediate return from a GUI-subsystem binary cannot pass as a project load. On Windows the extensionless link is not directly callable, so use `--group <name>` through the runner (or the resolved real path) instead of the bare per-group commands. `uv run python tools/audit_repository.py` checks tracked text for secret-like values and the legacy fixtures for personal data; its regex rules have their own tests in `tests/test_repository_audit.py`, and `tests/test_gui_test_runner.py` covers the runner's failure detection and executable resolution with synthetic subprocesses.

Install the optional single-sample explanation dependency separately with `uv sync --extra explain` (or `uv pip install -e ".[explain]"`). Without it, `tests/test_explanation.py`, `tests/test_explanation_cli.py` and `gui/tests/test_explanation.gd` skip or report the missing dependency, and ordinary prediction keeps working. The first explanation triggers numba JIT and the matplotlib font cache and can be slow; point `NUMBA_CACHE_DIR`, `MPLCONFIGDIR` and `PSYML_TEST_TMP` into `tmp/phase-C-worker/`. Automated checks cover the cumulative waterfall segments (base→output, top N + remainder), waterfall endpoints using the same atol/rtol as the core, GUI artifact view/open and persistence across changes, blocked context changes during computation, immediate cancel+restart, and chunked JSON plus large stderr. The CLI `explain --output-dir` export still writes only to a new/empty folder, falls back to a unique new subdirectory without changing an existing same-named CSV/model/background, and reports an error with no success marker for the same-source folder, missing artifacts or copy failure; it rejects a non-empty output directory and `--overwrite`, while the interface has offered no export entry since FR-020. Real-window appearance and many-predictor CJK figures still need human inspection, and passing headless tests does not replace it.

Fitted coefficients (FR-005) need no `explain` extra: `tests/test_coefficients.py` covers per-family coefficient/intercept reconstruction, `drop`+`none` identity passthrough, category values/types with underscore labels, removed all-missing column records, `drop_idx_`/per-column encoding mapping, training-dtype source, binary LDA sigmoid=probability and multi-class logistic softmax=probability axis semantics, and that a failed check (tolerance/shape/non-finite) returns `error` and refuses to publish; `tests/test_coefficients_cli.py` covers CLI export, overwrite refusal, unverified and failed-write states; `gui/tests/test_coefficients.gd` covers the results-page coefficient status and open entry, per-output-axis intercept/unit/fit-scope display, language switching and the absence of an export entry. `gui/tests/test_explanation.gd` adds background-row layout assertions (single line, not a collapsed column).

For manual review, load classification data; use target `target`, group `participant`, predictors `score` and `category`, Decision Tree and Dummy, group K-fold with 3 outer/2 inner folds. Add holdout and select no primary validation. Results should begin with a neutral selector; inspect each validation, switch all UI languages without losing choices, and check the small version label under the application name against `__version__` in the source `src/psyml/__init__.py` (a standalone package uses its bundled `BUILD.json`, generated from the same constant); the current source checkout shows the official version number `0.3.0`. On page 2 the new training output must appear under `training/run_*` in the result root. On page 4 confirm the output root row matches page 2, prediction writes `prediction/run_*/predictions.csv` (directly openable, and **Open prediction results folder** opens the run folder rather than the CSV), SHAP and coefficients land in new `run_*` directories under `explanation/` and `coefficients/`, none of the three blocks has an export entry, and legacy `run_*` folders directly under the root still open without being rewritten. Check gesture ownership: a gesture started on the page keeps scrolling the page past a nested table, a gesture started on the table scrolls only that table, and a ~250 ms pause starts a new gesture that may switch layers; immediately clicking another list or dragging a scrollbar after a scroll gesture must still select or move (the lock only affects wheel/swipe scrolling). During final writing the status must read "Finalizing and writing results…" with the bar not full, and the result page opens only after completion. Then run regression. Also check error copying, cancellation and retry. Tiny-sample R² warnings are expected in boundary tests. Automated success is not scientific acceptance. CI runs on Windows, macOS and Linux with `uv sync --locked --group dev --extra explain`, so the SHAP tests really execute instead of being skipped, and runs all 12 GUI groups through `tools/run_gui_tests.py` (the project validation step `--validate` uses the same runner and resolved executable); when the GUI step fails, `tmp/ci-gui` per-group logs are kept as a short-lived test artifact (synthetic test logs only, no added permissions, no release) so a platform failure still shows the complete group logs and summary; every SHAP-dependent `uv run` step (`uv run --extra explain pytest -q`, the `PSYML_PYTHON` step and the GUI runner) passes `--extra explain` explicitly so a sync cannot drop the extra; check the commit's CI results separately for each OS. The manual Windows test build in `.github/workflows/native-test-build.yml` also installs `explain` and `build` and runs the A/C/D bundle smokes (permutation/explanation/coefficients); both release platforms keep the `explain` dependency and those three smokes. It only keeps test artifacts, never publishes a release, and changing that workflow definition does not mean Windows native has been verified.

## Français

Installer selon le guide de développement et exécuter les commandes ci-dessus à la racine. `tests/` contient les tests du noyau, `gui/tests/` ceux de l’interface, et `examples/synthetic/` les paires CSV/JSON voisines. Les données publiques sont facultatives. N’utiliser que des données synthétiques pour les tests. Exécuter ces commandes dans les sources, pas dans une archive d’application autonome. L’audit exige aussi `legacy/` ; ne l’ignorer que si ce dossier est absent de la copie des sources. La copie des sources est désormais la version officielle `0.3.0` (source unique), avec les fonctions des phases A–D et les deux séries de correctifs issus des retours humains (première série FR-012–FR-016 ; seconde série : complément FR-016 et FR-017–FR-020) ; les paquets autonomes et PDF de distribution disponibles par version sont ceux listés sur la page Releases, tandis que les paquets v0.2.0 et antérieurs et leurs PDF ne contiennent ni ces fonctions ni ces correctifs. Les candidats de publication sont contrôlés par `tools/verify_release_artifacts.py`, qui lit réellement le contenu des ZIP/PDF et les empreintes au lieu d’une chaîne de succès dans un journal.

Définir `PSYML_PYTHON` avec l’environnement installé : `.venv/bin/python` sous macOS/Linux, `.venv/Scripts/python.exe` sous Windows. Les commandes propres à chaque système sont données plus haut. Les tests GUI nécessitent Godot 4.7.2. `tools/run_gui_tests.py` exécute les 12 groupes GUI headless l’un après l’autre (`--group <nom>` pour un seul groupe, `--list-groups` pour lister noms/scripts/marqueurs, `--timeout` pour la limite par groupe, 600 s par défaut). Un groupe ne réussit que s’il se termine avec le code 0, affiche son marqueur `PSYML_*_OK` et ne journalise ni `SCRIPT ERROR` ni marqueur `_FAILURE` ; Godot peut afficher des erreurs de script tout en sortant avec 0, donc le code de sortie seul ne suffit pas. Chaque groupe écrit sa sortie vers la console et vers `tmp/ci-gui/NN-<groupe>.log` (modifiable par `--log-dir` ou `PSYML_GUI_LOG_DIR`) au fur et à mesure : un groupe bloqué ou planté laisse donc sa sortie partielle dans le fichier ; le récapitulatif complet est toujours affiché et les échecs indiquent leur journal. En cas d’échec CI, `tmp/ci-gui` est téléversé comme artefact de test de 7 jours (réutilisation de l’upload-artifact épinglé du dépôt, aucune permission ajoutée, aucune release ; le dossier ne contient que des journaux de tests synthétiques). Le groupe de flux complet `ui_flow` attend 30 s par défaut un vrai calcul (`PSYML_TEST_RUN_TIMEOUT_SECONDS` peut allonger l’attente, jamais les assertions) ; en cas d’échec il écrit `ui_flow_failure.txt` avec la clé d’état, les dossiers attendus/réels canoniques et bruts, l’existence de `result.json`, l’état et le code de sortie du sous-processus du pont, et une fin de stderr bornée (sans lignes de données de recherche). Les commandes par groupe ci-dessus sont équivalentes pour le débogage manuel. Le lanceur résout Godot dans cet ordre : `--godot` explicite (chemin ou commande), puis `GODOT`, puis `GODOT4`, enfin la commande `godot` du PATH, et résout chaque résultat par `Path.resolve()` : les dossiers avec espaces et le lien sans extension créé sous Windows (par exemple `C:\Users\runneradmin\bin\godot`) exécutent donc le vrai `.exe`, sans shell ; un chemin invalide ou l’absence de candidat produit une erreur nommant les tentatives et un code non nul. `--validate` exécute `--headless --editor --path gui --quit` avec ce même exécutable, attend sa fin et exige le code 0, la bannière `Godot Engine v` et l’absence de `SCRIPT ERROR`/`_FAILURE` ; le retour immédiat de PowerShell sur un binaire GUI ne peut donc pas passer pour un chargement réussi. Installer séparément la dépendance facultative d’explication : `uv sync --extra explain` (ou `uv pip install -e ".[explain]"`).
